# 安装、升级与发布验收

当前产物为 `0.1.2-rc.5` 发布候选版，通过tgz离线分发。package.json保留private，未发布npm registry。支持核对过的DSH桌面/SDK版本为 `0.2.1-rc.5` 和 `0.2.2-rc.1`，运行时Node需>=22；本轮离线回归使用Node24。rc.5增加工具审批等待、Router通知与审批失效清理；历史费用待核对记录不会因升级而解除。

## 安装和配置

1. 保留最终tgz及SHA-256，使用DSH宿主的本地插件包安装功能安装核心 `dsh-plugin-longtask`；不同宿主安装界面以实际版本为准。这里没有另造或假设一条DSH安装CLI。
2. 在当前profile的bundle列表中只保留核心；开发profile可另行保留E2E。不要把联调消费者放入正式profile，也不要删除开发目录及验收档案。
3. 按 `release/config.example.yml` 设置已安装longtask实例的配置。不要再次插入第二个同名实例。工作目录和专家库必须实际存在，专家库需有divisions.json及专家Markdown。凭证由宿主提供，不写入本包。
4. 首次使用正式环境，给dataDir一个独立目录。旧开发`.longtask/state.json`不迁移进新库，38个联调任务保留原处。正式目录为空时，查询应返回0项。
5. **完整退出并重启DSH进程**，不能只关闭隐藏到后台的窗口，也不能仅依赖热重载。检查日志`user-entry:ready=true`，运行信息ready/userEntryReady为true、userEntryProtocol为3、moneyAccountingProtocol为1、routerNoticeProtocol为2、approvalWaitProtocol为1、userActionsProtocol/requestAccountingProtocol为1。新任务开工还需userQuestions.ask输入通道。

工具审批依赖宿主的 `approval/asked`、`approval/decided` 会话事件。主会话收到的是可见状态摘要，不会因此自动调用模型；实际批准或拒绝仍由用户在对应 Worker 的宿主审批卡片完成。重载时未结束的原审批会失效，任务暂停核对，不自动重放工具或假定用户批准。

未配置目录时默认使用当前用户：dataDir为 `~/.dsh/longtask`，专家库 `~/.dsh/agency-agents`，工作区 `~/Documents/deepseek-harness/default-workspace`。也可在启动DSH的进程环境配置 `DSH_LONGTASK_DATA_DIR`、`DSH_LONGTASK_EXPERTS_ROOT`、`DSH_LONGTASK_WORKSPACE`；实例显式配置优先。环境变量在模块加载时读取，改后要重启。工作目录不存在时正式提案会拒绝，不猜另一个写入位置。

正式bundle启用`acceptorReadOnly:true`：验收仅允许read/glob/grep/ls/working_directory，其他工具包括shell、write、edit均拒绝。它不能自行执行代码测试，执行者负责运行并提供证据，验收者读取产物与回执核对。需要不同验收能力时先明确权限范围，不能默默关闭只读以绕过失败。旧profile未开启该项时仍沿用旧能力集与提示词纪律。

## 普通用户操作

- 先说“列出我的长任务”，核对工作目录和真实列表。
- 提出明确目标和交付物，先看方案并调整人选与分工；在宿主输入框填写人民币总上限后开工。Agent的suggestedBudgetCny仅为建议。
- “暂停任务 task_…”；“恢复任务 task_…，沿用原预算”。恢复需确认，不自动加额。
- “回答任务 task_… 的问题：……”：答复经宿主确认，先交给原负责人再恢复；不能解除用户主动暂停或预算问题。
- “给任务 task_… 补充信息：……”；信息不明确先澄清，不改变完成标准。
- “任务 task_… 已交付，但漏了……，按这条标准纠错”：确认新标准后同ID升版本，已用量与总上限继承。
- “在任务 task_… 基础上新增……”：建立关联待确认方案，明确独立预算，另行确认。
- “把任务 task_… 的执行专家A换为B，原因……，剩余事项……”：确认后交接，原会话撤权，验收人不变。

正式工具不新增独立Router模型。自动建议、自然语言分类仍由主会话Agent完成；本版不承诺其所有表达均已通过实机验收。主会话费用由DSH管理，不计入已确认Worker任务账本。

## 预算异常与诊断

模型响应完全缺用量、字段非法或无法对应已准入请求时，任务会保持暂停，`accountingIssue`显示原因。金额任务保留未知请求的在途金额并暂停；历史Token任务重启可能将孤儿预留保守转入已结算，但不会消除待核对标记。缺usage的TRANSPORT错误也不能擅自宣称零费用重试。此版不提供让模型清除该标记的工具，需人工依据原始请求证据核对处理。

首轮输入仍依赖配置的声明基线；宿主隐藏的动态系统提示、工具定义及供应商内部行为并非全部可观测。本版提供预留准入、已观测用量结算与异常停机，不能宣传为任意模型/适配器下绝不超支的供应商硬限额。

未知投递不重发、不自动恢复；应核对真实收件/产物再走后端对账流程。不要用恢复、重新start或新建同目标任务规避这些暂停。

包内只读诊断器：

```powershell
node "<安装目录>/scripts/diagnose.mjs" "<dataDir>" "<taskId>"
```

## 升级与回退

升级前先暂停相关任务并完整退出DSH；复制整个dataDir作备份，另存profile配置和旧tgz。安装新包后使用原dataDir可保留任务与已用量，必要时先在数据副本中核对。不得在两个DSH进程中同时写同一个JSON库。

回退时先暂停并退出，恢复旧包、对应的升级前数据备份和profile，再启动。旧版本不识别新的用量异常标记，**不要把新版本已运行的数据库直接交给旧版继续执行**。回退不是重新放行未知外部动作；原来需对账的任务继续保持暂停。

卸载只移除核心实例/bundle；保留dataDir、产物和费用记录，避免卸载等于删除成果。回归用E2E仍可在独立开发profile保留。

## 最终桌面验收场景（尚未执行）

这组操作由用户在已移除E2E的正式profile中发起；不由本包自动启动。单个实机任务由用户填写人民币总上限，例如 **¥2**，不自动追加。模型不得代填；输入金额即确认完整方案，必须亲自核对。预算不足就保留失败证据、定位原因，不通过加额强行取得通过。

1. 确认干净安装的列表为0；提出“写一个不超过20行的本地存储比较，交付一个Markdown文件”的方案，先关闭金额输入或提交无效金额：无Worker、无执行预算。再确认模型建议没有被当作已批准金额。
2. 调整待确认人选/标准，核对新版本，亲自填写金额确认开工；检查task.confirmed记录的用户会话及callId。立即暂停，查看paused/user，再确认恢复；最终读取实际文件、独立验收结果与用量。
3. 在同一已交付任务上要求补一条可核对依据，确认纠错重开：同ID新版本，费用累计、人民币总上限仍为原金额；余额不足则保持暂停，不加额。
4. 以该任务为父任务提出额外要求，建议预算¥1、**保持未确认且无实际金额上限**，核对关联proposed且无派工。这个未确认子任务不增加本轮执行预算。
5. 澄清答复、换人、只读拦截和预算异常已具离线回归，但还需真实宿主证据才能按原实施文档§6宣布全部行为验收。不得用本手册代替通过记录。

记录宿主版本、配置（去除凭证）、主会话/Worker/验收会话ID、任务ID、最终产物哈希、预算账本和审批轨迹。更新总验收时引用新证据，不覆盖旧阶段冻结清单。

## 本版金额口径与升级边界

- 默认仅配置deepseek-official/deepseek-flash，按照2026-11-06核对的官方高峰价保守核算（input 2、cacheRead 0.04、cacheWrite 2、output 8元/百万Token），2026-12-06北京时间0时到期。配置modelPrices可覆盖；缺价或过期不会免费继续。来源：https://api-docs.deepseek.com/zh-cn/quick_start/pricing/
- 首版不判定峰谷时段和中国法定节假日，展示核算费用而非平台实扣。也不将账户余额差当作本任务费用；第三方付费工具、用户主会话不在任务模型预算内。
- 旧Token任务及其已用量不自动换算；同一已有任务禁止切换计费单位。金额任务不可通过Token追加绕过上限。纠错重开沿用原金额和核算记录。
- getMoneyBudget(taskId)返回人民币总上限/核算/在途/可用；getModelExpenses(taskId)返回最近20笔请求和价格快照；完整历史仍在同一持久化账本。正式longtask_tasks详情包含这些费用记录。
- 新安装包须独立核对版本0.1.2-rc.3及SHA-256；release/verify-installed.mjs是0.1.1-rc.1首次安装的历史验证脚本，不适用于本版或已有正式任务的数据库，不得清空数据库以让旧脚本通过。
- 真实桌面验收尚未执行：金额输入面板、提交后自动执行/验收、暂停恢复、旧Token任务兼容、余额/平台账单的核对。离线全绿不代替这些证据。

## 0.1.2-rc.2状态回传验收补充

当前候选版本升级到0.1.2-rc.2，保留0.1.2-rc.1的冻结证据，不覆盖旧包。核对routerNoticeProtocol:1。金额输入及执行验收之后，还要验证：Worker截断接续或自动暂停时，正确主会话出现longtask-status的notice摘要，另一个会话没有串消息；展开能看暂停原因、账本和主会话恢复指引。主会话关闭期间状态保留待投递，重新加载后显示一次。单纯通知不得启动Router模型或自动增加预算。

旧正式任务仍按原Token账本运行；未记录主会话身份的旧任务不会凭首个在线会话推断Router。用户在指定主会话完成确认/批准恢复后才建立绑定。主会话审批本身不代表预算已追加，Worker直接发送继续仍受任务状态与预算准入限制。
